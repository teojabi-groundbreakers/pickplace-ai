# 전국 상권 현황 연구용 데이터

## 목적과 범위

확보한 전국 상가정보와 주민등록 인구를 각각 지역별 기술통계로 준비한다. 상가 현황은 원본 행정동 코드와 상권업종 소분류 코드별 점포 수이며, 인구는 주민등록 기준 읍면동별 인구다. 조회 결과는 연구용 현황이며 사업의 적합도, 위험도, 창업 성공 확률이나 미래 매출 예측이 아니다.

현재 자료에는 전국 행정동·업종별 매출 정답과 여러 시점의 연속 이력이 없다. 따라서 전국 매출 성장 모델의 학습이나 성능 검증에 사용하지 않으며, 기존 서울 모델을 다른 지역에 적용하지 않는다. 이 기능은 규칙에 따른 집계이며 학습된 AI 모델이 아니다.

## 원본과 기준 시점

| 원본 | 로컬 위치 | 확인한 파일상의 기준 | 제공값 |
|---|---|---|---|
| 소상공인시장진흥공단 상가(상권)정보 | `data/raw/nationwide/stores/` 아래 `20260930` 원본 폴더 | 폴더 레이블 `20260930`, 지역별 파일명 `202609` | 상가 행정동 8자리 코드, 소분류 업종 코드, 업소 정보 |
| 행정안전부 주민등록 인구현황 | `data/raw/nationwide/resident_population/202610_연령별인구현황_읍면동.csv` | `2026-10` | 행정구역 10자리 코드와 월말 인구 |

파일명에 있는 기준 레이블은 실제 자료의 공개일이나 입수일을 증명하지 않는다. 점포와 인구의 시점도 다르며, 10월 인구를 9월에 이미 알 수 있었던 값으로 취급하지 않는다. 인구 파일은 주민등록 인구로 유동인구와 다르고 외국인이 제외된다. 읍면동 파일에는 시도·시군구 상위 집계 행도 포함되어 있으므로 이를 읍면동에 더하지 않는다.

상가 8자리와 인구 10자리 지역 코드의 원본 체계와 유효 기간을 아직 공식적으로 대조하지 못했다. 코드의 자릿수를 자르거나 0을 덧붙이거나 이름만 이용해 결합하지 않는다. [행정표준코드 FAQ](https://www.code.go.kr/qna/faqL.do) 8번의 행안부 주소코드 변경내역과 [SGIS 소지역 통계 이용매뉴얼](https://sgis.kostat.go.kr/html/attachFiles/%EA%B0%9C%EC%A0%95%ED%8C%90%20SGIS%20%EC%86%8C%EC%A7%80%EC%97%AD%20%ED%86%B5%EA%B3%84%20%EC%9D%B4%EC%9A%A9%EB%A7%A4%EB%89%B4%EC%96%BC.pdf)의 기준시점별 연계 자료를 확인해야 한다. 자료의 존재만으로 소진공 8자리 필드의 공식 변환 방식이 검증되는 것은 아니다.

상권업종 소분류는 서울 서비스 업종이나 한국표준산업분류와 동일하다고 가정하지 않는다. 분류와 코드가 개정될 수 있으므로 다른 시기·기관 자료와 결합하기 전 원본 정의와 이력을 확인한다.

## 가공 결과

`scripts.prepare_nationwide`는 원본을 읽어 각각 별도 집계 파일 `stores.csv`, `population.csv`와 데이터 출처·지문을 기록하는 `manifest.json`을 준비한다. 코드 체계가 확인되기 전 두 집계는 서로 연결하지 않는다. 원본이나 산출물을 기존 경로에 덮어쓰지 않고, 데이터와 산출물은 Git에 포함하지 않는다.

프로젝트 루트에서 아래처럼 실행한다. `--output-dir`은 아직 존재하지 않는 새 경로로 지정한다. 상가 기준 레이블은 전달한 파일들의 이름을 보고 지정하는 값이며, 파일의 실제 관측·공개 시점이나 지역별 완전성을 프로그램이 독립 검증한 값은 아니다. 이 버전은 상가 레이블 `20260930`만 지원한다.

```bash
PYTHONPATH=src:. .venv/bin/python -m scripts.prepare_nationwide \
  --stores data/raw/nationwide/stores/*/*.csv \
  --population 'data/raw/nationwide/resident_population/202610_연령별인구현황_읍면동.csv' \
  --store-reference-label 20260930 \
  --population-reference-month 2026-10 \
  --output-dir data/processed/nationwide/snapshot-202609-202610
```

명령의 와일드카드는 해당 위치의 모든 CSV를 포함한다. 같은 폴더에 다른 기준 시점의 파일이 있다면 혼합하지 말고, 사용할 원본 파일만 명시적으로 나열한다. 필요한 시도 파일이 빠지면 그 범위는 집계에 포함되지 않는다.

2026-11-09 로컬 검증에서는 상가 원본 16개 2,753,778행에서 404,575개의 지역·업종 집계와 인구 원본에서 3,625개 읍면동 행을 생성했다. 결과는 `data/processed/nationwide/snapshot-202609-202610-20261109/`에 보관한다. 전국 완전성과 최초 공개일은 검증하지 못했다.

원본 출처와 이용조건은 각각 [상가(상권)정보](https://www.data.go.kr/data/15083033/fileData.do) 및 [행정동별 연령별 인구현황](https://jumin.mois.go.kr/ageStatMonth.do)에서 확인한다. 상가 파일은 영업 중인 업소의 현황으로, 단일 스냅샷에서 개업·폐업 건수를 산출하지 않는다. 제공자료가 실제 전체 점포를 빠짐없이 포함하거나 영업 상태가 현재와 일치한다고 보장하지 않는다.

## 연구용 API

전국 현황은 기존 서울 예측 API와 분리된 연구용 API에서 점포와 인구를 각각 조회한다. 내부 호출용 별도 API 키가 필요하며, 매출 예측·점수·주민 수 대비 점포 수를 만들어 반환하지 않는다. 없는 코드, 누락된 자료나 확인되지 않은 값은 0으로 대체하지 않는다. 데이터가 없거나 유효성을 확인할 수 없으면 조회 불가 사유를 반환한다.

프로젝트 루트에서 검증할 가공 결과 디렉터리와 API 키를 설정하고 로컬 서버를 실행한다. 키는 실제 사용값을 환경변수로 설정하며 저장소에 기록하지 않는다.

```bash
export PICKPLACE_NATIONWIDE_DATA_DIR=/path/to/trusted/nationwide-output
read -rs PICKPLACE_NATIONWIDE_API_KEY
export PICKPLACE_NATIONWIDE_API_KEY
PYTHONPATH=src .venv/bin/uvicorn pickplace_ai.nationwide_api:app \
  --host 127.0.0.1 --port 18002
```

별도 터미널에서 `GET /health`로 준비 상태를 확인하고, 아래 세 조회에는 `X-API-Key` 헤더를 지정한다. `/health`를 제외한 모든 조회는 인증이 필요하다.

| API | 입력 | 응답 |
|---|---|---|
| `GET /research/nationwide/metadata` | 없음 | 가공 데이터 출처·기준과 제약 |
| `GET /research/nationwide/stores` | `region_code`: 상가 원본 8자리, `industry_code`: 상권 소분류 6자리 | 해당 원본 코드의 점포 수 |
| `GET /research/nationwide/population` | `region_code`: 인구 원본 10자리 | 해당 원본 코드의 월말 주민등록 인구 |

형식이 잘못된 입력은 422, 인증 오류는 401, 산출물 준비·무결성 오류는 503이다. 자료가 없는 코드는 HTTP 200 응답에 `status=unavailable`과 사유·null 값을 담는다. 값이 0인 관측과 자료 부재를 구분한다. 이 API는 외부 공개용이 아니며, 실제 서비스에 연결하기 전 접근 제어와 백엔드 연동을 검증해야 한다.

원본 파일과 가공 결과는 신뢰할 수 있는 경로에서 관리하고 실제 인증키는 환경변수로만 주입한다. 연구용 데이터의 운영 적합성, 실제 Spring Boot 연동과 배포는 별도 확인이 필요하다.

## 후속 작업

1. 상가·인구의 원본 코드 체계 및 기준일별 공식 연계표를 확보하고, 행정구역 변경·분할·통합과 미연결 항목을 검증한다.
2. 2026년 9월 기준 인구와 과거 점포 스냅샷을 확보해 기준 시점·업종 분류·공개일을 확인한다. 개폐업 이력은 독립 자료로 검증한다.
3. 지역별 매출 정의와 지역·업종·기간이 맞는 연속 이력, 과거 공개 버전을 확보한다. 데이터 출처별 학습·검증 범위를 분리한다.
4. 지역별 검증 결과와 단순 기준을 비교한 뒤에만 전국 예측 모델의 활용 범위를 정한다.
