# 서울 서비스 업종 순차 분기 평가

관련 이슈: [#11](https://github.com/teojabi-groundbreakers/pickplace-ai/issues/11)

## 목적

한 시점의 시험 오차에 의존하지 않고, 여러 과거 기준 분기에서 같은 표본으로 후보를 비교한다. 평가 업종은 커피 전문점 `CS100010`, 분식전문점 `CS100008`, 제과점 `CS100005`다. 행정동·업종 합계의 **전년 동기 대비 추정매출 성장률**을 평가하며 개별 매장 매출·수익·성공확률을 예측하지 않는다.

기본 훈련 범위는 입력에 있는 서울 전체 업종이다. 기존 단기 모델과 같은 `near_term_forecast.build_frames`·`matrix`·`predict` 및 공통 `features.feature_record`를 사용한다. 선택적으로 `--training-scope service3`를 지정하면 3개 업종만 훈련하는 별도 실험이 된다. 두 훈련 범위의 결과를 혼동하지 않는다.

이 도구는 모델을 저장하거나 현재 공유 모델·FastAPI를 교체하지 않는다. 과거 원본의 최초 공개 시점과 당시 버전을 확인하지 못했으므로 **수정 스냅샷의 후향 시뮬레이션**이다.

## 분할과 비교 조건

| 항목 | 기본값·정의 |
|---|---|
| 기준 분기 | `2024Q1`~`2025Q4`, 8개 분기 |
| 예측 거리 | 다음 분기와 2분기 뒤를 각각 직접 평가 |
| 후보 선택 | `2024Q1`~`2025Q2`의 6개 기준 분기, 3개 업종 공통 표본 전체 MAE 최소 |
| 보고 구간 | 마지막 2개 기준 분기 `2025Q3`, `2025Q4`. 후보 선택에서 제외 |
| 훈련 라벨 | 기준 분기보다 1분기 이전까지의 대상 분기만 사용 |
| 입력 특징 | 각 표본의 기준 분기까지 연속 5분기, 미래 매출을 특징에 넣지 않음 |
| 후보 | 0% 성장, 최근 전년 동기 성장률 유지, 기존 Huber SGD, 절대오차 HGB |
| HGB | `loss=absolute_error`, 80회, 최대 잎 15개, 학습률 0.05, seed 42 |
| 전처리 | 매 fold 훈련 자료에만 결측 대치·업종 인코더·스케일러 적합 |
| 최저 성장률 | 기존 단기 추론 함수와 같은 −100% 하한 |

라벨을 1분기 이전으로 제한하는 것은 `--label-embargo-quarters 1`이라는 **실험 가정**이며 서울시의 실제 공개 주기가 검증됐다는 뜻이 아니다. `--as-of`에는 실제 확보·사용 가능한 기준일을 전달한다. 자료의 `available_at`이 해당 날짜보다 늦으면 실행을 거부한다. 과거 분기를 `as_of`로 위장하지 않는다.

마지막 보고 구간도 이전 연구에서 일부 확인한 자료다. 이번 실행에서 후보 선택과 분리하더라도 새롭고 독립적인 시험 성능으로 주장하지 않는다. 2026Q3 정답은 이 실행으로 생성되지 않는다.

## 실행

실제 정규화 CSV를 보유한 AI 프로젝트 루트에서 새 출력 경로를 사용한다.

```bash
PYTHONPATH=src:. OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -m scripts.evaluate_seoul_rolling \
  --input data/processed/seoul/seoul-2021-2026q2-20261104.csv \
  --output reports/seoul-rolling-evaluation-new \
  --as-of 2026-11-20
```

`--origins 2024Q1 2024Q2 ...`로 고유한 오름차순 기준 분기를 지정할 수 있다. `--report-origins`는 마지막 몇 개를 보고 구간으로 남길지 정한다. 선택·보고 구간에는 각각 최소 한 개의 기준 분기가 필요하다. 훈련이나 세 업종 중 한 업종의 평가 자료가 없는 분기는 조용히 건너뛰지 않고 오류로 알린다.

## 산출물 해석

산출물은 Git 제외 `reports/` 아래에 저장한다. 기존 출력 경로는 덮어쓰지 않으며 입력 CSV 해시를 실행 전후 대조한다. 모델 파일과 원본 관측값을 복사하지 않고 집계만 남긴다.

| 파일 | 내용 |
|---|---|
| `fold-metrics.csv` | 분기·예측 거리·업종·후보별 훈련 표본 수, 훈련 라벨 마감 분기, 평가 표본·누락 정답·평가 가능 비율, MAE·중앙절대오차·P90 |
| `aggregate-metrics.csv` | 선택/보고 구간별·예측 거리별·업종별 및 3개 업종 전체 오차 |
| `summary.json` | 입력·코드·출력 해시, 패키지 버전, 훈련 범위, 선택/보고 분기, 선택 후보, 특징 생성 제외 사유와 해석 제한 |

오차 단위는 **%p**다. 10% 성장과 15% 성장의 차이는 5%p다. 전체 MAE는 모든 해당 행의 절대오차를 합쳐 계산하며 분기별 MAE의 단순 평균이 아니다. 오차 상위 10%가 시작되는 P90과 중앙절대오차도 함께 본다. 극단 성장률·저매출 사례는 임의 삭제하지 않는다.

`evaluation_coverage`는 해당 기준 분기에 관측된 업종별 지역 조합 중 이력과 정답이 있어 평가에 들어간 비율이다. 실서비스의 보류 정책을 적용한 제공률이나 정확도를 뜻하지 않는다. 분모는 `base_scope_rows`, 특징이 생성된 수는 `eligible_feature_rows`, 정답 결측은 `missing_target_rows`로 구분한다.

`ALL_SERVICE3`는 세 업종을 합친 값이다. 후보마다 같은 평가 행을 사용하고, 유한하지 않은 예측이나 집계 오차는 실패로 처리한다. 일부 후보의 실패 행을 버려 오차를 낮추지 않는다.

## 2026-11-20 실자료 실행 결과

위 명령의 기본 설정으로 실제 서울 정규화 CSV를 평가했다. 입력은 2021Q1~2026Q2이며 기록된 확보 기준일은 2026-11-03~04, 이번 `as_of`는 2026-11-20이다. 전체 업종을 훈련하고 세 서비스 업종만 평가했으며 라벨 엠바고는 1분기다. 선택에는 2024Q1~2025Q2, 보고에는 2025Q3·2025Q4 기준 분기를 사용했다.

산출물은 로컬 `reports/seoul-rolling-20261120/`에 보관했다. 요약의 입력 해시와 현재 입력 CSV, 출력 CSV 두 개의 해시, 실행기·단기 모델 코드·공통 특징 코드의 해시가 모두 일치함을 대조했다. 아래에는 원본 관측값 없이 집계 지표만 기록한다.

후보 선택 구간에서 두 예측 거리 모두 Huber SGD가 선택됐다. 다음 표는 **선택에 사용하지 않은 보고 구간**에서 같은 행으로 비교한 결과다. 다음 분기의 표본은 2,398건, 2분기 뒤는 2,397건이다.

| 후보 | 다음 분기 MAE (%p) | 2분기 뒤 MAE (%p) |

Huber SGD의 보고 구간 중앙절대오차는 다음 분기 7.185%p·2분기 뒤 9.306%p, P90은 각각 24.978%p·33.578%p다. 업종별 결과는 다음과 같다.

| 업종 | 다음 분기 표본 | 다음 분기 MAE (%p) | 2분기 뒤 표본 | 2분기 뒤 MAE (%p) |

전체 8개 기준 분기의 업종별 평가 가능 비율은 96.07~100%였다. 이는 이력과 정답을 확보해 평가할 수 있는 비율이며, 실서비스 보류 정책에 따른 제공률은 아니다. 이번 조건에서 HGB 추가는 Huber SGD보다 낮은 전체 MAE로 이어지지 않았다. 분식의 2분기 뒤 오차와 큰 개별 오차의 원인을 후속 분석 대상으로 남긴다.

보고 구간도 기존 연구에서 확인한 기간이므로 독립 시험이 아니다. 기존에 발표한 MAE와는 대상 분기·표본·훈련 조건이 달라, 숫자가 낮다는 이유로 기존 공유 모델의 정확도가 개선됐다고 비교하지 않는다. 새 운영 모델을 발행하거나 현재 공유 모델·FastAPI를 교체하지 않았다.

## 성장률 변환 비교 (2026-11-21)

기존 Huber SGD와 성장률을 `asinh`로 변환해 학습한 Huber SGD를 비교했다. 변환은 저매출 구간에서 발생할 수 있는 큰 성장률의 학습 영향을 낮춘다. 예측에는 `sinh` 역변환과 기존 -100% 하한을 적용했다. 입력 특징, 학습 행, 분기별 학습 제한, 평가 표본은 두 후보에 동일하게 적용했다.

2024Q1~2025Q2 기준 분기의 평균절대오차(MAE)로 후보를 비교했다. 다음 분기는 변환 후보가 15.065%p로 기존 15.100%p보다 낮았다. 2분기 뒤는 기존 후보가 18.329%p로 변환 후보 18.474%p보다 낮았다.

2025Q3·Q4를 기준으로 한 보고 구간 결과는 다음과 같다. 화살표는 기존 Huber에서 변환 후보로 바뀐 값을 뜻한다.

| 다음 분기 | 2,398 | 15.900 → 15.339 | 7.185 → 7.078 | 24.978 → 25.815 | 18 → 20 |

두 후보 모두 같은 2,425개 기준 조합 중 2,402개에서 입력 특징을 만들었다(99.05%). 실제 매출과 대조 가능한 비율은 다음 분기 98.89%, 2분기 뒤 98.85%였다. 실서비스의 결과 제공률은 제공 단계의 별도 보류 기준에 따라 달라진다.

다음 분기 후보는 평균 오차가 개선됐지만 큰 오차 건수도 늘었다. 2분기 뒤에는 선택 구간에서 더 낮은 오차를 보인 기존 Huber를 선택했다. 이번 결과는 2026Q2까지 확보한 수정 스냅샷의 후향 비교로 기록한다. 변환 후보의 다음 분기 성능은 신규 실측이 확보되면 기존 후보와 함께 재검증한다.

```bash
PYTHONPATH=src:. .venv/bin/python scripts/evaluate_seoul_rolling.py \

```

`--output`에는 새 경로를 지정한다. 실행 결과에는 집계 지표, 후보 선택 결과, 입력·코드·산출물의 SHA-256이 포함된다.

## 다음 분기 P90 악화 분석과 보정 후보 (2026-11-21)

앞 실험에서 다음 분기 두 후보의 2,398개 예측을 기준 분기·서울 원본 행정동 코드·업종이 동일한 행끼리 대조했다. 기준 모델의 전체 P90인 24.978%p를 넘는 사례가 변환 후 새로 36건 생겼고 17건은 그 아래로 내려갔다. 새로 넘어간 36건 중 30건의 전년 동기 매출은 1억 원 이상 10억 원 미만이었다. 22건은 실제 성장률이 25% 이상 100% 미만이었고 11건은 −25% 미만이었다. 전체 MAE 개선은 실제 성장률이 100% 이상인 38건에 집중됐다. 나머지 2,360건의 평균 오차는 0.066%p 늘었다. 실제 성장률 구간은 결과를 대조할 때만 사용했다.

표의 화살표는 기존 Huber → 전체 `asinh` → 전년 동기 매출 1억 원 미만만 `asinh` 순서다.

구 이름은 확인된 서울 코드↔SGIS 코드 대응과 2025년 6월 말 SGIS 구 이름으로 연결했다. 2,230건(93.0%)이 연결됐고 168건은 구별 집계에서 미연결로 표시했다. 업종별·전체 집계에는 2,398건을 모두 사용했다. 같은 기준으로 보면 영등포구 분식전문점의 P90은 17.99→25.34%p(30건), 성북구 제과점은 24.11→29.78%p(35건)였다. 개별 사례로 2025Q3 기준 강북구 미아동 제과점은 절대오차가 23.43→30.11%p로 늘었다. 동별 사례는 개별 예측의 변화로 기록했다.

변환 모델과 기존 모델의 50:50 혼합, 완화한 `asinh`, 100%를 넘는 학습 타깃만 변환하는 방식, 전년 동기 매출이 1천만 원 또는 1억 원 미만인 경우에만 변환 모델을 사용하는 방식을 비교했다. 매출 기준은 기존 진단의 구간 경계를 사용했다. 일부 후보는 위 오차를 검토한 뒤 설계했으므로 아래 결과는 탐색에 사용한 후향 평가다.

| 전년 동기 매출 1천만 원 미만만 변환 모델 | 14.861 | 25.050 | 15.572 | 24.978 | 18 |
| 전년 동기 매출 1억 원 미만만 변환 모델 | 14.914 | 25.419 | 15.202 | 25.025 | 19 |

후보 선택은 2024Q1~2025Q2 기준의 7,211건에서 P90과 오차 100%p 초과 건수가 기존 Huber 이하여야 한다는 조건으로 비교했다. 이 조건을 충족한 후보는 기존 Huber였다. 1억 원 미만에만 변환 모델을 적용하면 보고 구간에서 전체 변환 대비 MAE와 P90이 함께 낮아졌다. 추가 확인한 2026Q1 기준 1,203건에서도 전체 변환 대비 MAE가 16.466→16.279%p, P90이 28.079→26.478%p로 줄었으나 오차 100%p 초과는 16건으로 기존 Huber 15건보다 많았다. 1천만 원 미만 후보는 보고 표본 23건에만 적용됐으며, 보고 P90은 기존 Huber와 같았다. 매출 구간별 후보는 연구 결과로 보관하고 새 실측에서 재확인한다.

```bash
PYTHONPATH=src:. .venv/bin/python scripts/evaluate_seoul_next_quarter_tail.py \
  --input data/processed/seoul/seoul-2021-2026q2-20261104.csv \
  --name-reference 'data/raw/seoul/sales/서울시 상권분석서비스(추정매출-행정동)_2025년.csv' \
  --region-mapping data/raw/seoul/fit-reference/20250630/mapping.csv \
  --sgis-reference data/raw/seoul/fit-reference/20250630/sgis-seoul-admin-dong-areas-20250630.csv \
  --output reports/seoul-next-quarter-tail-20261121 \
  --as-of 2026-11-20
```

`reports/`에 전체·업종·구·매출 구간별 지표와 행별 대조 결과를 저장한다. `private-paired-errors.csv`에는 실제 성장률과 비교 매출이 들어 있다. 새 출력 경로에 실행하며 생성 결과는 Git 제외 경로에 보관한다.

## 다음 판단

선택 후보가 여러 분기·업종에서 기준 모델보다 나은지 확인한 뒤 별도 재학습·결과 제공 기준 실험을 진행한다. 보고 구간의 결과를 보고 후보·임계값을 다시 조정하면 해당 구간도 선택에 사용한 것으로 기록해야 한다. 이 평가만으로 운영 승인, 예측구간 보정, 위험도·적합도 타당성 검증 또는 FE·BE 통합이 완료되지는 않는다.
