# 서울 보류 기준 통과 사례로 학습한 서울·경기 공동 모델

## 학습 방법

서울의 각 지역·업종·대상 분기에 대해 예측 전 네 분기 매출만 확인해 기존 서울 저매출·급증·급감 신호에 해당하지 않는 사례만 학습에 사용했다. 대상 분기의 실제 매출이나 예측 오차는 필터에 사용하지 않았다. 경기도에는 서울의 금액 기준을 적용하지 않고 기존 학습 범위를 유지했다. 제외한 사례는 학습에 사용하지 않았을 뿐 원본에서 삭제하지 않았다.

서울과 경기 출처를 구분하고 원천별 학습 가중치를 50:50으로 맞춘 **하나의 공동 추정기**다. 서울 업종 코드만 학습 범주로 사용하며 경기 업종을 서울과 연결하지 않는다. 새로운 서울 업종은 미확인 범주로 처리한다. 평가에는 학습 기간을 2025Q2까지로 제한하고 2025Q3을 비운 뒤 2025Q4를 사용했다. 2026Q2도 같은 평가 모델로 재사용 비교했다. 평가 이후 2026Q2까지 학습해 최종 후보를 별도로 만들었다.

| 자료 | 평가용 학습 | 최종 재학습 |
|---|---:|---:|
| 서울 보류 기준 통과 | 188,617건 | 245,071건 |
| 경기 | 30,465건 | 152,405건 |

기존 고정 기준은 저매출 전년 비교 원본 관측값 약 1,054만원 미만, 최근 분기 원본 관측값 약 810만원 미만, 연속 분기 증가율 +206.66% 초과 또는 감소율 -72.79% 미만이다. 하나라도 해당하면 보류한다. 이 숫자는 실제 오류나 지역의 위험을 판정하지 않는다. 기준은 2025Q2에 실제 라벨이 존재하는 사례의 입력으로 계산하고 오차를 본 뒤 선택한 사후 기준이다. 과거 학습 전체에 고정 적용한 것은 현재 스냅샷을 이용한 회고 분석으로 과거 실시간 처리의 재현이 아니다.

## 같은 평가 사례 비교

아래 평균 절대오차(MAE)는 전년 동기 대비 성장률의 예측과 실측 차이이며 단위는 %p다. 서울 표본은 라벨·네 분기 이력이 있는 사례 중 기존 네 신호를 통과한 동일 집합이다. 실제 전체 요청의 제공률을 뜻하지 않는다.

| 2025Q4 반복 평가 | 이전 업종 반영 공동 모델 | 서울 통과 사례만 학습한 공동 모델 |
|---|---:|---:|
| 서울 통과 14,112건 | **19.30%p** | 19.36%p |
| 서울 전체 16,002건 | **68.85%p** | 70.82%p |
| 서울 보류 1,890건 | **438.82%p** | 455.04%p |
| 경기 전체 30,524건 | **38.69%p** | 40.13%p |

서울 통과 14,112건은 평가 가능한 서울 16,002건의 88.19%다. 서울 보류 사례의 수치는 실제 서비스에서 보류한 사례를 평가 목적으로만 계산한 값이며, 사용자에게 그 예측을 제공한다는 의미가 아니다. 서울 업종을 사용하지 않고 통과 사례만 학습한 후보의 서울 통과 MAE는 20.07%p, 경기 MAE는 39.84%p였다. 이 연구에서는 이미 확인한 2025Q4의 서울 통과 MAE를 기준으로 두 후보 중 업종 반영 후보를 선택했다. 이는 경기 성능 개선이나 독립 선택을 보장하지 않는다.

이미 확인한 2026Q2 재사용 비교에서도 서울 통과 14,085건은 21.54→21.60%p, 경기 30,469건은 54.52→55.82%p로 높아졌다. 2025Q4와 2026Q2는 반복 사용해 독립 시험이 아니다. 위 지표는 2025Q2까지 학습한 **평가 모델**의 결과며 2026Q2까지 별도 재학습한 최종 후보의 독립 성능이 아니다.

2026Q3 자료 없이 이전 분기에서도 서울 단독 롤링 비교를 추가했다. 2024Q2·2024Q4·2025Q2 각 평가에서 이전 학습 이력으로만 별도 기준을 정했을 때, 서울 업종 입력 모델의 통과 사례만 학습한 후보는 전체 사례로 학습한 후보보다 세 분기 모두 오차가 높았다. 이는 서울 단독 실험이며 공동 모델의 직접 평가가 아니다. 최신 수정본을 사용했고 과거 실제 공개 시점이 확인되지 않아 당시 실시간 예측의 재현이나 독립 성능 검증은 아니다. 상세 분기별 기준·지표는 보고서에 있다.

## 사용 범위와 한계

사용자 요청에 따라 필터를 적용한 공동 모델을 만들었지만, 같은 평가 범위에서 기존 업종 반영 후보 대비 서울과 경기 오차가 모두 높았다. 따라서 정확도가 개선됐다고 결론 내리지 않으며 기존 통합 FastAPI의 모델을 자동 교체하지 않는다. 기존 API의 서울 보류 정책은 기존 모델 지문에 묶여 있다. 새 모델과 정책을 연결하려면 별도의 무결성·입력·시점·지원 범위 검증과 서울 보류 시 null·사유 처리가 필요하다. 경기도에는 서울 금액 기준을 적용하지 않는다.

경기 입력은 `review_only_not_training_or_prediction`으로 표시된 미승인 검토 후보여서 기존 데이터 문서의 학습 제한과 충돌한다. 사용자가 요청한 후향 연구에 한해 사용했으며 단위·집계·지역 경계 검증 전에는 운영이나 확정 성능 근거로 쓰지 않는다. 2026Q3 자료는 사용하지 않았다. 원본 수집 시점·정정 이력, 2024년 경기 중복, 코드·지역 경계 및 과거 공개 시점도 확인이 필요하다.

## 산출물과 재실행

`artifacts/seoul-guard-filtered-20261109/`에 평가용 모델, 별도로 재학습한 `final-model.joblib`, 지문과 학습 범위를 기록한 메타데이터가 있다. `reports/seoul-guard-filtered-20261109.json`에는 전체 비교와 서울 단독 분기별 진단이 있다. 산출물은 Git에서 제외되며 신뢰할 수 있는 로컬 모델만 읽는다. 체크섬은 신뢰할 수 없는 joblib의 안전성을 보장하지 않는다.

AI 프로젝트 폴더에서 실행하며 기존 출력은 덮어쓰지 않는다.

```bash
PYTHONPATH=src:. OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  .venv/bin/python -m scripts.train_seoul_guard_filtered \
  --seoul data/processed/seoul/seoul-2021-2026q2-20261104.csv \
  --seoul-manifest data/processed/seoul/seoul-2021-2026q2-20261104.manifest.json \
  --gyeonggi data/processed/gyeonggi/monthly-review-20261109/candidates.csv \
  --gyeonggi-manifest data/processed/gyeonggi/monthly-review-20261109/manifest.json \
  --snapshot 2026-11-09 \
  --output artifacts/seoul-guard-filtered-new \
  --report reports/seoul-guard-filtered-new.json
```
