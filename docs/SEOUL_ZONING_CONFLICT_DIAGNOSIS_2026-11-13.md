# 서울 용도지역 중첩 원인 진단과 처리 기준

작성일: 2026-11-13 (Asia/Seoul)

## 결론

현재 `overlap_ambiguity_share`는 **같은 코드가 여러 번 나온 비율이 아니라**, 주거·상업·공업·녹지·미분류 도형 중 서로 다른 분류의 도형이 같은 면적을 덮는 비율이다. 같은 분류의 도형은 먼저 합집합으로 묶으므로 단순 중복 행은 이 비율에 직접 더해지지 않는다. `PRESENT_SN`도 고유 키가 아니어서 번호만으로 중복 도형을 판정할 수 없다.

최신 서울 원본의 큰 중첩은 두 종류로 나뉜다.

| 구분 | 원본에서 확인한 내용 | 판단 |
| --- | --- | --- |
| 신림동 등 오래된 중첩 | 준주거·일반상업 행의 `SCLAS_CL`에 중분류 코드가 반복되어 공식 ZIP 코드표의 빈 값과 다르다. 이 행들이 `unknown`으로 분류되고 같은 유형의 정상 도형과 거의 전부 겹친다. 신림동의 53.1846%는 2023-10 자료부터 지속된다. | 코드 형식의 동치 가능성을 검토할 수 있으나, 원천 입력 규칙 확인 전 기본 분류는 유지한다. |
| 2026-03 이후 급증 | 신규 주거 도형 `11000UQ111PS202509030001`과 자연녹지 도형 `11000UQ111PS202509030002`이 각각 101·127개 행정동에 걸친다. 앞의 행은 코드 계층이 달라 `unknown`이며 기존 주거 도형과 99.98% 중첩한다. 뒤의 행은 기존 주거 도형과 넓게 겹친다. | 새 녹지를 통째로 제외하면 실제 용도지역 변경을 잃을 수 있다. 두 행의 원천 관계를 확인할 때까지 후향 학습에 사용하지 않는다. |

2025-08→2026-03 ZIP에서 면적 가중 중첩은 **0.718%→2.530%**, 20% 초과 행정동은 **3→19개**로 증가했다. 최신 2026-09 ZIP에서 위 신규 두 원본 행만 임시 제외해 계산하면 중첩은 **2.368%→0.425%**, 품질 재검토 행정동은 **65→13개**로 감소한다. 이는 영향도 실험이며 원본 삭제나 영구 제외의 근거가 아니다.

| 2026-09 행정동 | 전체 중첩 | `unknown`이 관여한 면적 | 알려진 유형끼리의 면적 |
| --- | ---: | ---: | ---: |
| 신림동 | 53.185% | 53.185% | 0.000% |
| 홍제1동 | 42.431% | 8.970% | 33.461% |
| 시흥4동 | 35.545% | 23.054% | 12.491% |
| 필동 | 34.342% | 0.584% | 33.757% |
| 홍은2동 | 30.774% | 29.706% | 1.068% |

표의 두 오른쪽 값은 같은 공간을 두 번 더하지 않도록 분리한 비율이다. 반올림 때문에 표시 합이 전체와 미세하게 다를 수 있다.

## 고시 자료와 공간 대조

[서울특별시 고시 제2025-393호](https://eum.go.kr/web/gs/gv/gvGosiDet.jsp?seq=614617)는 2025-07-24 용도지역·용도구역 변경을 고시했다. [서울시의회 업무보고](https://mas.smc.seoul.kr/attach/record/SEOUL/appendix/a11/A0069176.pdf?time=20260419160027)는 도시자연공원구역 내 주거·상업지역을 자연녹지로 변경해 자연녹지가 약 **4.8㎢ 증가**했다고 설명한다.

원본 도형을 같은 면적 좌표계로 맞춰 비교하면 2026 신규 자연녹지 도형 49.420㎢는 2025-08 기존 **녹지 44.618㎢와 주거 4.803㎢**를 덮는다. 4.803㎢는 공표된 약 4.8㎢와 매우 가깝다. 따라서 새 녹지 도형은 변경 후 통합 경계를 담고, 과거 주거 도형 일부가 최신 ZIP에 함께 남았을 가능성이 높다. **이는 공간 대조에 따른 추론**이다. 두 신규 행은 같은 `NTFC_SN=11000NTC202507300001`을 공유하고, [도시자연공원구역 원본](https://data.seoul.go.kr/dataList/OA-21135/S/1/datasetView.do)에서도 이 번호를 볼 수 있으나, 해당 번호와 제2025-393호의 직접 매핑 및 개별 도형의 대체 범위는 아직 확인되지 않았다. 두 신규 도형끼리도 약 0.1095㎢ 겹쳐 별도 확인이 필요하다.

## 구현 및 사용

- 기본 면적 비율은 계속 엄격하게 분류하고 `training_eligible=false`로 둔다. 기존 면적 비율에 `overlap_unknown_involved_share`와 `overlap_known_only_share`를 추가해 코드 미분류를 포함한 중첩과 알려진 유형 간 중첩을 구분한다. 두 진단 비율의 합은 `overlap_ambiguity_share`이며 면적 비율의 분할 합에 다시 더하지 않는다.
- `repeated_midcode_review_candidate()`는 원본 코드표에서 `SCLAS_CL`만 빈 값으로 바꾸면 정확히 유효하고 명칭도 일치하는 행에 **검토 힌트**를 준다. 기본 분류 결과는 바꾸지 않는다. 2026 신규 주거 행처럼 중분류 자체가 다른 경우는 후보가 아니다. `--classification-scenario repeated_midcode_alias`는 이 힌트만 적용한 **별도 반사실 산출물**을 만든다. 검토한 원본 ZIP 6종의 해시와 버전당 후보 3행을 검사해 새로운 입력에서는 멈춘다. 출력 파일명·메타데이터에 시나리오를 명시하고 `training_eligible=false`를 유지한다.
- `scripts/diagnose_seoul_zoning_conflicts.py`는 선택한 행정동의 원본 도형 쌍을 CSV로 추적한다. 행번호·기하 해시·원본 코드·고시관리코드·분류 사유·교차 면적을 함께 기록한다. **쌍별 교차 면적은 세 도형 이상이 겹칠 때 합산하면 중복 계산된다.** 원본 ZIP과 결과 CSV는 Git 제외 `data/` 아래에 보관한다.

```bash
PYTHONPATH=src:. .venv/bin/python scripts/diagnose_seoul_zoning_conflicts.py \
  --version 20260911 --region-code 11620695 --region-code 11410620

PYTHONPATH=src:. .venv/bin/python scripts/prepare_seoul_zoning_research.py \
  --version all --classification-scenario repeated_midcode_alias \
  --output-root data/processed/seoul/zoning_alias_review
```

버전 비교에는 `--version 20250805`, `20260304`, `20260911`을 각각 실행하고, 기존 파일을 덮어쓰지 않도록 출력 경로를 확인한다. 원본 파일이 별도 작업트리에 있다면 `--zoning-root`와 `--boundary-archive`를 지정한다.

실제 6개 ZIP에 반복 코드 동치 시나리오를 적용한 결과, 각 버전에서 원본 **3행·행정동 5곳**의 중첩 비율이 달라졌다. 신림동은 **53.1846%→0.00012%**로 줄지만 2026-09 전체 재검토 행정동은 **65→64곳**이다. 따라서 이 코드 형식만 고쳐서는 2026년 광역 도형 중첩이 해결되지 않는다. 이는 가정 기반 결과이며 모델 특징이나 서비스 응답에 반영하지 않는다.

## 고시 후 도형 대체 가설 검증

새 자연녹지 도형이 기존 주거·상업 도형을 대체했을 가능성을 **별도 반사실 시나리오**로 시험한다. 2025-08 원본과 행 식별값·코드·명칭·투영 도형 해시가 모두 같은 2026년 주거·상업 행에 한해서, 새 녹지와 겹치는 부분만 비교용 도형에서 잘라낸다. 새 녹지 행은 버전별 ZIP SHA-256·원본 행번호·도형 해시·코드로 고정한다. 과거와 달라진 행, 신규 주거 도형, 신규 주거↔녹지 중첩은 그대로 남긴다. 원본 ZIP과 기본 엄격 분류 결과는 바꾸지 않는다.

| 원본 버전 | 엄격 분류 면적 가중 중첩 | 시나리오 면적 가중 중첩 | 재검토 행정동 | 정확히 일치해 처리한 과거 행 | 처리 면적 합집합 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2026-03 | 2.530% | 1.755% | 68→57곳 | 224행 | 4.803㎢ |
| 2026-09 | 2.368% | 1.640% | 65→55곳 | 215행 | 4.518㎢ |

2026-09에는 새 녹지와 기존 주거·상업의 겹침 약 **4.803㎢** 중 **0.285㎢**가 2025-08 도형과 정확히 일치하지 않아 남는다. 2026 신규 주거와 신규 녹지 사이의 약 **0.1095㎢** 중첩도 처리하지 않는다. 이 수치는 원인 가설의 영향도이지 실제 용도지역의 확정 판정이나 매출 예측 오차 개선이 아니다. 시나리오 CSV와 메타데이터에는 `training_eligible=false`, `scenario_approved_for_training=false`, 원본 해시와 남은 겹침을 기록한다.

```bash
PYTHONPATH=src:. .venv/bin/python scripts/simulate_seoul_zoning_supersession.py \
  --version 20260911 \
  --output-root data/processed/seoul/zoning_supersession_scenario
```

원본이 별도 작업트리에 있으면 `--zoning-root`와 `--boundary-archive`를 함께 지정한다. 다른 버전 또는 해시가 달라진 원본은 실패하도록 제한했다. 담당기관이 원본 도형의 대체 관계와 코드 형식을 확인하기 전에는 두 시나리오 모두 학습 입력·운영 API에 사용하지 않는다.

## 적용 전 확인할 것

1. 제2025-393호의 변경 전후 도면과 원본시스템에서 `NTFC_SN=11000NTC202507300001` 및 두 신규 행의 대체·폐지 관계를 확인한다. 새 녹지의 4.803㎢ 변경 후보와 신규 주거↔녹지 0.1095㎢ 상충을 구분한다.
2. 반복된 `SCLAS_CL` 입력이 원본에서 허용하는 동치 표현인지 확인한다. 승인된 경우에도 코드표·명칭·원본 해시·도형 지문을 검증한 특정 행만 재분류한다.
3. ZIP의 최초 이용 가능일과 행정동 경계의 과거 유효기간을 따로 증빙한다. 고시일은 ZIP의 최초 공개일이 아니다. 이 조건이 확보되기 전에는 후향 모델 입력이나 FastAPI의 확정 지역 성격으로 사용하지 않는다.

제2025-393호 담당부서는 [토지이음 고시 페이지](https://eum.go.kr/web/gs/gv/gvGosiDet.jsp?seq=614617)에 서울시 시설계획과(02-2133-8458)로 표시된다. 문의할 때에는 아래 세 가지를 원본 파일명·원본 행번호·`NTFC_SN`과 함께 제시한다.

1. `11000NTC202507300001`이 제2025-393호와 직접 대응하는지, 신규 UQ111 녹지·주거 행이 기존 도형을 어느 범위에서 대체하는지.
2. 준주거·일반상업 행에서 `SCLAS_CL`에 `MLSFC_CL`을 반복한 값이 유효한 동치 코드인지, 신규 주거 행의 `MLSFC_CL=UQA100`은 어떤 의미인지.
3. 각 ZIP의 최초 공개·이용 가능일과 도형 기준일, 행정동 경계 ZIP의 공간 기준일을 확인할 수 있는 공식 기록이 있는지.

[서울시 원본 안내](https://data.seoul.go.kr/dataList/OA-21136/S/1/datasetView.do)는 이 공간자료를 법적 효력이 없는 참고자료로 명시한다. 원본과 기존 모델·API는 변경하지 않는다.
