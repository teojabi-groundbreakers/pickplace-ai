# FE 데모 기준 상권 진단 항목과 데이터 확보 점검

> 이 문서는 최초 점검 시점의 기록이다. 이후 BE 게시·AI 연동 진행 상태는 백엔드 이슈 #36과 지표별 분기 계약을 함께 확인한다.

점검일: 2026-11-09. 로컬 `pickplace-frontend`를 **읽기 전용**으로 살펴보고 `pickplace-ai`의 원본·가공 산출물과 API 문서를 대조했다. FE에 화면이 있다는 사실과 실제 값의 수집·산출·제공 가능 여부는 다르다. 이 문서는 개발 우선순위를 정하기 위한 점검이며, 실제 FE·BE 연동이나 새 지표 구현 결과가 아니다.

FE `src/data/demo.ts`의 점수·시계열·영향 요인·지도 마커·문구는 가상 예시다. `src/components/AnalysisPanel.tsx`도 데모에 SAMPLE 고지를 표시한다. 데모 업종·지역 목록이나 숫자를 실제 지원 범위·예측값으로 해석하지 않는다. 아래에서 **원본 보유**, **계산·연계 준비**, **현재 API 제공**을 구분한다.

> **후속 진행:** 이후 서울 원본의 매출·점포·상주인구·길단위인구를 분기별로 조회하는 별도 연구 API를 추가했다. 기존 통합 성장률 API의 응답은 그대로이며 FE 월별 지표와 실제 FE·BE 연동은 여전히 미완료다. 아래 표는 최초 점검 시점의 통합 API 기준이며, 새 기능과 검증 범위는 [서울 분기 현황 API](SEOUL_INDICATORS_API.md)를 참고한다.

FE는 기본적으로 6개월 또는 12개월의 **월별** 추이, `만원` 단위의 점포당 월평균 매출과 `명` 단위의 일평균 유동인구를 표시한다. 서울 원본의 관측 주기는 분기이고 경기 매출은 월별이므로, 화면 형식에 맞추기 위해 누락된 월이나 단위를 만들어서는 안 된다. 분기 단위 표시 또는 데이터별 주기 지원은 FE·BE와 별도로 협의한다.

## 3. 코드·기간·응답에서 먼저 해결할 점

1. **지역 코드:** FE에서 전달하는 H10, 서울 상권의 8자리 코드, 경기도 원천 10자리, 전국 상가 8자리·인구 10자리는 각각 보존한다. 자릿수 삭제·추가나 이름만으로 연결하지 않는다. 공식 대응과 변경 이력을 기준 시점별로 검증한다.
2. **업종 코드:** FE 업종과 서울 CS·경기 중분류·전국 상권 소분류는 서로 다른 체계다. 공식 정의·시점별 대응 및 다대다·미연계 처리를 정한다.
3. **시간·비교 범위:** 값마다 관측 기간과 최초 공개·취득 시점을 구분하고, 월·분기·스냅샷을 혼용하지 않는다. `지역 평균`의 지역 범위, 업종, 분모, 집계 방식과 기준 시점을 먼저 합의한다.
4. **API 계약:** 통합 성장률 API와 전국 현황 API는 별도다. 원본이 있어도 통합 API가 해당 값을 반환하는 것은 아니다. BE에서 출처와 불가 사유를 보존하고 FE 전체 응답으로 조합하는 계약·구현이 필요하다.
5. **결측 표시:** 현재 통합 API는 불가 시 기계식 사유를 반환하지만 모든 사유에 한국어 메시지가 있는 것은 아니다. FE의 점수·추이 값은 null을 처리하지만 요약 문자열, 비교 배열·지도 객체 등 전체 응답 계약은 별도다. 보류 사유·상세의 DTO 변환과 사용자 표시를 FE·BE와 합의한다.
6. **과거 검증:** 최신 수정 스냅샷을 받았다는 사실은 당시 공개됐다는 근거가 아니다. 예측 기준일에 사용 가능했던 자료만 사용하고, 공개·정정 이력이 불명확하면 이를 독립 전향 검증으로 표현하지 않는다.

## 4. 데이터 확보와 구현 우선순위 제안

| 순서 | 작업 | 완료 판단 기준 |
|---|---|---|
| 1 | 지표 정의·출처 구분 | FE 월평균 매출, 일평균 유동인구, 지역 평균, 개폐업률의 산식·지역·업종·기간·단위를 FE·BE·AI가 합의한다. |
| 2 | 서울 원본 우선 점검 | 이미 있는 매출·점포·상주·길단위인구의 컬럼 정의, 시점별 범위·공개일과 코드 관계를 검증한다. 원본의 존재와 화면 제공 가능을 별도로 기록한다. |
| 3 | 경기·전국 이력 보완 | 경기 매출 단위·월 합산과 코드 유효성을 확인하고, 인구 과거 이력·경기 유동인구·다시점 점포·개폐업 자료를 조건에 맞게 확보한다. |
| 4 | 현황 API·연동 설계 | 검증된 값부터 BE가 조합할 계약을 만들고 출처·기간·단위·결측 사유를 포함한다. 실제 FE·BE 통합 테스트를 별도로 수행한다. |
| 5 | 추정·점수·추천 검증 | 매출 성장률과 현황을 구분해 보여주고, 점수나 추천은 목표·산식·근거·평가가 정해질 때까지 미제공으로 둔다. |
| 6 | 정책 안내 | 기업마당의 직접 API와 개별 공고 활용 조건을 확인해 원문·신청 기간을 제공한다. 예측 입력으로 바로 가정하지 않는다. |

인구의 성별·연령·시간대 상세와 지원사업 안내는 현 FE 데모 결과 패널의 독립 항목이 아니라 **후속 개선 제안**이다. 주민등록인구를 유동인구나 매장 고객 수로, 공고를 실제 수혜나 정책 효과로 표현하지 않는다.
