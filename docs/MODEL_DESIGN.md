# 모델 및 진단지표 설계

## 1. 범위

전국 점포·인구·시설 자료는 기본진단에 활용하고, 성장 예측은 같은 기준의 과거 매출을 확보·검증한 지역에서 제공한다. 첫 실험 대상으로 서울 행정동·카페를 제안했지만 실제 코드·유효 표본은 원본 확보 후 확정한다.

지역 집계로 개별 가게의 매출·폐업확률이나 창업 성공확률을 예측했다고 표현하지 않는다. 데이터가 없는 지역은 수치를 만들어 제공하지 않는다.

## 2. 첫 목표와 특징

한 관측은 코드 체계가 명시된 `행정동 × 업종 × 분기`다. 기준 분기 t의 입력으로 t+1의 전년 동기 대비 추정매출 증가율을 예측한다.

```text
y = sales[t+1] / sales[t-3] - 1
```

특징 생성은 `features.py`가 학습·추론에서 공통으로 담당한다. 달력상 t-4부터 t까지 5개 분기의 매출 이력이 필요하다. 결측 분기를 제거하고 이전 행을 이전 분기로 간주하지 않는다. 분모 0·결측인 라벨은 제외한다.

입력은 매출·과거 매출·증가율·변동성, 점포·개폐업수 비율, 인구, 면적 대비 점포 수, 분기다. 선택 지표 결측은 학습 구간에서 적합한 imputer가 처리하며 실제 결측을 0으로 사전 치환하지 않는다. 전부 결측인 특징도 열 순서를 유지한다.

현재 수집 자료에 필요한 원본 인구·면적이 없다면 해당 지표와 적합도는 미산출일 수 있다. 이 단계에서 전국 공통 데이터 어댑터까지 구현한 것은 아니다.

## 3. 공개 시점과 검증

- `available_at`은 실제 사용 가능 시점이다. 사이트 수정일이나 다운로드일을 과거 최초 공개일로 간주하지 않는다.
- 학습 표본의 입력은 기준 관측의 available_at까지 알려진 과거 자료만 사용한다.
- t+1 분기가 이미 끝난 뒤 알게 된 관측은 과거의 미래 예측 표본으로 만들지 않는다.
- 전체 목표 분기를 기준으로 train/validation/test를 나눈다. 기본 validation·test는 각각 마지막 2개 분기다.
- train 라벨은 첫 validation 예측 전에, validation 라벨은 첫 test 예측 전에 알려졌어야 한다.
- 전처리는 train에서만 적합한다. 현재 버전은 train+validation으로 자동 재학습하지 않는다.
- zero-growth, recent-growth, Ridge, 지정한 boosting 후보를 validation MAE로 선택한다. 단순 기준이 더 좋으면 기준 모델이 선택될 수 있다.
- 모든 후보의 test 지표를 기록하지만 test 정답으로 후보를 선택하지 않는다.
- 지원 scope는 train과 test에 모두 등장한 코드 체계·지역·업종 조합이다. 새 지역 일반화를 자동으로 주장하지 않는다.

MAE·RMSE는 증가율 단위와 퍼센트포인트 단위를 함께 기록한다. `0.05`는 성장률 5%이고, MAE 0.05는 평균 오차 5퍼센트포인트다. 회귀 결과를 정확도 95%처럼 표현하지 않는다.

과거 공개 버전이 없는 최신 수정 자료로 학습할 때는 당시 상황 재현의 한계를 별도로 기록해야 한다. 데이터 준비만으로 점포 수 변화·추정매출 산정 변경·표본 편향이 해결되지는 않는다.

## 4. 모델 후보

기본 환경에서는 scikit-learn HistGradientBoosting을 비교할 수 있다. LightGBM은 `lightgbm` extra와 실행 환경을 준비한 뒤 명시적으로 선택한다. 설치가 실패했을 때 다른 알고리즘으로 조용히 대체하지 않는다.

학습 결과는 항상 experimental이다. 합성 데이터 실험은 실제 상권 성능 검증이 아니다. 운영 승인 절차·지역별 허용 오차·실제 매출 정의를 팀이 검토해야 한다.

## 5. 진단지수 초안

현재 지표 정책은 `draft-v0.1`이다. 다음 상수는 파이프라인 검증을 위한 공개된 임시 기준이며 실제 사업성 검증을 거친 가중치가 아니다.

| 지수 | 고정 구성 | 현재 계산 |
|---|---|---|
| 위험지수 | 전년 대비 매출 감소, 폐업수/현재 점포수 | 감소율 25%·현재 점포 대비 폐업비 15%를 각각 100점 기준으로 두고 0~100으로 제한, 두 항목 각 50% |
| 기본 적합도 | 주민수/동종 점포수, 동종 점포수/면적 | 점포당 주민 500명과 km²당 점포 50개를 임시 기준으로 두고 수요·경쟁 지표 각 50% |

- 위험지수는 높을수록 위험하며 적합도는 높을수록 해당 초안 기준에 긍정적이다.
- 폐업수/현재 점포수는 기관의 공식 폐업률과 다를 수 있어 `closing_stock_ratio`로 구분한다.
- 적합도는 현재 배후인구·경쟁에 관한 단순 지수다. 임대료·실제 구매전환·최적 입지·이익률까지 반영하지 않는다.
- 고정 구성 중 자료가 빠지면 해당 지수는 null이다. 남은 변수의 가중치를 임의로 재배분하지 않는다.
- 실제 화면 제공 전에 비교집단, 임계값, 가중치와 정책 승인 여부를 합의한다.

## 6. 예측 근거

기본 구현은 TRAIN 중앙값을 기준으로 한 단일 특징 치환 민감도다. 한 특징만 기준값으로 바꿨을 때 예측값 차이를 계산한다.

```text
delta_growth = original_prediction - prediction_with_one_feature_replaced
```

이 방법은 SHAP이 아니고 가산적 기여도나 인과효과도 아니다. 서로 연결된 파생변수를 하나만 바꾸면 실제로 존재하지 않는 특징 조합이 될 수 있다. 전역 중요도나 경제적 원인으로 확대 해석하지 않는다. 결측·동일 값은 설명에서 제외하고 큰 차이의 최대 3개 항목을 반환한다.

SHAP은 향후 후보이며 아직 기본 의존성과 코드에 포함하지 않는다. 숫자형 신뢰도·성공확률·보정된 예측구간도 구현하지 않는다.

## 7. 산출물

`model.joblib`, `metadata.json`, `evaluation.json`, `MODEL_CARD.md`를 한 버전 디렉터리로 관리한다. 메타데이터에는 데이터 지문, 출처, 코드 범위, 특징 스키마, 시간 분할·정보 기준, 패키지 버전, 선택 기준과 한계가 들어간다.

joblib 로더는 체크섬·특징 순서·환경을 확인한다. 체크섬은 손상 확인이며 신뢰할 수 없는 pickle을 안전하게 만드는 기능이 아니다.
