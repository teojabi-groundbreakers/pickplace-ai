# 서울 용도지역 특징 학습 준비

작성일: 2026-11-12 (Asia/Seoul)

상태: **원본 6종의 행정동별 면적 비율 전처리 완료. 시점·경계 검증 전이므로 매출 모델 학습에는 미반영.**

## 목적과 입력

행정동을 주거·상업·공업·녹지 중 한 유형으로 단정하지 않고, 각 용도지역의 **면적 비율**과 미분류·미피복 비율을 연구용 특징 후보로 만든다. 거주·유동인구는 별도의 관측 지표이며, 법정 용도지역을 인구만으로 추측해 대체하지 않는다. 면적 비율과 매출의 연관이 확인되더라도 매출 변화의 원인이라고 설명하지 않는다.

- 원본: [서울시 용도지역(도시지역) 공간정보](https://data.seoul.go.kr/dataList/OA-21136/S/1/datasetView.do)의 ZIP 6종(목록상 수정일 2023-10-24, 2024-11-07, 2025-03-20, 2025-08-05, 2026-03-04, 2026-09-11)과 [서울시 상권분석서비스 영역-행정동](https://data.seoul.go.kr/dataList/OA-22160/S/1/datasetView.do)의 경계 ZIP 1종.
- 위치: Git 제외 `data/raw/seoul/zoning/urban_area/source_versions/<버전>/source.zip` 및 `data/raw/seoul/boundaries/official_polygon/imported_20261112/source.zip`. 원본 ZIP의 SHA-256을 메타데이터와 대조한다.
- 코드: 원본 매출과 경계 모두 **8자리 행정동 코드 값**으로 대조했다. 공간 CSV의 `region_code_system=seoul-adstrd-8`과 기존 학습 스냅샷의 `seoul-adstrd`는 이름만 달라서, 결합 전 같은 8자리 체계임을 명시적으로 검사해야 한다. 코드 자르기나 이름 매칭은 사용하지 않는다. 보유 매출 표본의 425개 코드가 경계와 정확히 일치하지만, 과거 경계 동일성을 뜻하지 않는다.

## 생성한 연구용 산출물

`requirements-zoning.txt`의 선택 의존성을 설치하면 `scripts/prepare_seoul_zoning_research.py`로 원본 ZIP에서 면적 비율 CSV를 만들 수 있다. EPSG:5174 용도지역과 EPSG:5181 경계를 동일한 면적 좌표계 EPSG:6933으로 변환해 행정동 단위로 겹친다. 원본 코드표의 계층과 명칭이 맞는 도형만 네 유형에 배정한다. 상충하는 유형의 중첩, 미매핑 코드, 안전하게 복구되지 않은 도형은 `unknown_share`에 포함하고, 경계 안에서 덮이지 않은 면적은 `uncovered_share`로 분리한다. 원본 도형은 수정하지 않는다.

결과는 Git 제외 `data/processed/seoul/zoning_area_shares/zoning_shares_<버전>.csv`와 각 `*.metadata.json`에 있다. 여섯 버전 모두 425행이며 행정동 코드 중복이 없다. 모든 행의 주거+상업+공업+녹지+미분류+미피복 비율 합이 1이고, 출력 해시가 메타데이터와 일치한다. 최초 공개일·도형 기준일·과거 경계 유효기간이 확인되지 않았으므로 **모든 CSV 행과 메타데이터의 `training_eligible`은 `false`**다.

2026-11-13 개선본은 `overlap_ambiguity_share`를 `overlap_unknown_involved_share`와 `overlap_known_only_share`로 더 나눠 원인을 추적한다. 두 열은 진단용이며 주거·상업·공업·녹지·미분류·미피복의 분할 합에 다시 더하지 않는다. 기존 여섯 CSV는 보존했고, 개선본은 새 출력 경로에서 검증했다.

| ZIP 목록상 수정일 (엄격 분류) | 면적가중 미분류 | 면적가중 유형 충돌 | 품질 재검토 행정동 |
| --- | ---: | ---: | ---: |
| 2023-10-24 | 0.65% | 0.50% | 23/425 |
| 2024-11-07 | 0.70% | 0.67% | 16/425 |
| 2025-03-20 | 0.73% | 0.71% | 18/425 |
| 2025-08-05 | 0.74% | 0.72% | 18/425 |
| 2026-03-04 | 2.56% | 2.53% | 68/425 |
| 2026-09-11 | 2.40% | 2.37% | 65/425 |

품질 재검토 기준은 연구용으로 `unknown_share > 5%`, `overlap_ambiguity_share > 5%`, `uncovered_share > 1%` 중 하나다. 이는 모델 학습 승인 기준이 아니다. 2026-09 자료에서 신림동(`11620695`)의 미분류·중첩 비율은 각각 약 53.18%다. 원본 준주거·일반상업 두 행의 세부 코드 형식이 코드표와 달라 `unknown`으로 처리되고, 같은 유형의 정상 도형과 거의 전부 겹친 것이 주원인이다. 서로 다른 정상 용도지역이 동 면적의 절반 이상을 겹쳐 지정했다는 뜻은 아니다. 최신 버전에서는 5% 초과 미분류가 65개 동, 20% 초과가 18개 동이다. 신규 도형 두 행과 공식 고시의 관계, 구체적인 진단 방법은 [서울 용도지역 중첩 원인 진단](SEOUL_ZONING_CONFLICT_DIAGNOSIS_2026-11-13.md)에 정리했다.

재생성이 필요하면 프로젝트 루트에서 **기존 결과와 다른 출력 폴더**를 지정한다. 스크립트는 기존 결과를 덮어쓰지 않는다.

```bash
.venv/bin/python -m pip install -r requirements-zoning.txt
PYTHONPATH=src:. .venv/bin/python scripts/prepare_seoul_zoning_research.py \
  --version all --output-root data/processed/seoul/zoning_area_shares_recheck
```

## 학습에 연결할 조건

1. 목표 분기 `t`의 특징은 직전 분기 `t-1` 말까지 **실제로 사용 가능했고 그 시점에 유효한** 용도지역 버전과 행정동 경계를 사용한다. `src/pickplace_ai/seoul_zoning_time.py`는 증빙된 날짜·해시·유효기간·참조가 없으면 차단한다. 파일 목록의 수정일, ZIP 타임스탬프, DBF `CREATE_DAT`는 최초 공개일이나 법적 효력일의 증거로 쓰지 않는다. 현재 보유한 메타데이터는 이 검증을 통과하지 못한다.
2. 당시 행정동 경계의 도형과 코드 유효기간을 확인한다. 2021~2024년 매출에는 424동, 2025년 이후에는 425동이 있으며 `11740690`(둔촌1동)은 이전 매출 표본에 없다. 현재 경계를 과거 전 기간에 자동 소급하지 않는다. 2021~2022년은 현재 확보한 2023년 이후 공간 ZIP으로 복원하지 않는다.
3. 위 조건이 검증된 뒤 서울 매출 연구 모델의 목표 분기별 `t-1` 특징 프레임에 `(base_period, 8자리 행정동 코드)`로 many-to-one 결합한다. 버전 선정과 코드 체계 확인에 실패하거나 품질 재검토인 행은 특징을 채우지 않고 제외 이유를 기록한다. 학습과 추론의 특징 계산 경로를 일치시킨다.
4. 동일한 기간·업종·품질 통과 표본과 기존 매출 보류 정책에서 `매출+업종` 기준선과 `매출+업종+용도지역 면적 비율` 후보를 비교한다. 분기별 커버리지, MAE·중앙 절대오차·90백분위 절대오차, 지역·업종별 오류를 함께 기록한다. 용도지역을 넣었다는 이유만으로 정확도 향상을 주장하지 않는다.

시점 증빙이 별도로 확보된다는 **가정 아래** 2025Q4 목표에는 2025-08 자료가, 2026Q2 목표에는 2026-03 자료가 후보가 된다. 2026-09 자료를 2026Q2까지의 학습·평가에 넣으면 미래 정보가 섞인다. 해당 후보 공간 CSV는 각각 **18동**, **68동**을 품질 재검토 대상으로 표시한다. 매출 표본의 제외 건수와 모델 성능은 학습 프레임을 확정한 뒤 별도로 계산한다.

2025Q4와 2026Q2는 기존 모델 개발 중 이미 여러 번 검토한 목표 분기이므로 새 후보의 독립 시험 구간으로 주장하지 않는다. 매출 원본 자체의 과거 공개 버전도 미확인이어서 현재의 비교는 수정본 기반 후향 연구에 한정된다. 새로운 미검토 시점의 관측 매출을 확보하고 첫 공개 시점을 검증한 뒤 전향 성능을 평가한다.
