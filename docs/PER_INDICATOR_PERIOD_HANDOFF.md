# 지표별 최신 분기 제공: FE·AI 구현 방향

작성일: 2026-11-16 (Asia/Seoul)

상태: [백엔드 이슈 #36](https://github.com/teojabi-groundbreakers/pickplace-backend/issues/36#issuecomment-6910272203)의 정책 합의와 **AI 내부 계약 테스트**를 정리했다. FE·BE 공개 응답은 아직 지표별 기준 분기를 제공하지 않는다.

## 결정한 제공 방식

- 성장 예측·위험도·적합도는 **지표마다** 분석일(`asOf`)에 사용할 수 있고 지역·업종 및 원천이 승인된 가장 최근의 기준 분기를 선택한다. 세 지표의 기준 분기가 같을 필요는 없다.
- 각 결과에 `basePeriod`, `status`, 값 또는 `null`, 제공 불가 `reason`을 함께 둔다. 성장 예측에는 `targetPeriod`와 비교 분기도 둔다. 기준 분기를 정할 수 없는 지표의 `basePeriod`는 `null`로 두고 사유를 표시하는 방안을 BE와 확정한다.
- 예를 들어 **승인된 입력이 있다는 가정하에** Q3 적합도와 Q2 위험도를 같은 응답에 둘 수 있다. FE는 카드마다 `2026Q3 기준`, `2026Q2 기준`을 명시한다. 서로 다른 시점의 결과를 하나의 종합점수, 동일 시점의 평가 또는 원인·결과 관계로 합치지 않는다.
- 한 지표를 제공할 수 없어도 다른 지표와 기본 통계는 보존한다. 0과 결측을 구분하고, `null`을 0점으로 바꾸지 않는다. 전역 AI 상태는 지표별 가용성을 대신하지 않는다.
- 성장 예측은 선택된 **성장용 입력 분기**에서 정해지는 대상 분기를 그대로 쓴다. 대상 분기가 분석일에 이미 끝났다면 기본 `/predict`의 `target_not_future`를 유지한다. 다른 지표의 최신 분기를 이유로 성장 대상만 임의로 앞당기지 않는다.
- 앞선 논의의 “최근 완료 분기에서 직전 한 분기까지” 허용 범위를 **지표별로도 적용할지**와 자료가 더 오래됐을 때의 사유 코드는 BE·FE와 최종 확정한다. 확정 전에는 무제한 과거 분기를 자동 선택하지 않는다.

### 기간이 다른 결과의 예시

다음은 **2026-11-16 분석일에 각 입력이 승인됐다고 가정한 계약 예시**이며 실제 관측·계산 결과가 아니다.

| 지표 | 입력 기준 분기 | 예측 대상 | 표시 |
|---|---|---|---|
| 성장 예측 | 2026Q2 | 2026Q3 | `null` · `target_not_future` (대상 분기가 이미 종료됨) |
| 위험도 | 2026Q2 | 해당 없음 | Q2 입력이 모두 검증되면 Q2 기준 초안 지수 |
| 적합도 | 2026Q3 | 해당 없음 | Q3 입력이 모두 검증되면 Q3 기준 초안 지수 |

## 현재 계약과 제안하는 공개 응답

| 항목 | 현재 구현 | 다음 공개 응답에서 필요한 내용 |
|---|---|---|
| 기준 분기 | FastAPI 요청·응답과 Spring·FE가 단일 `basePeriod`를 사용 | 성장·위험도·적합도 각각의 `basePeriod`. 단일 최상위 필드를 모든 지표의 기간처럼 쓰지 않음 |
| 성장 예측 | `growth.target_period`, `comparison_period`, 값·상태·사유 | 성장용 `basePeriod`와 대상·비교 분기를 함께 표시. 미래 대상 조건 유지 |
| 위험도·적합도 | 각 지표의 값·상태·사유, 공통 분기 헤더 | 각 지표의 기간과 값·상태·사유를 같은 카드·보고서에 표시 |
| 기본 통계 | AI와 별도로 조회 | AI 지표가 일부 또는 전부 보류되어도 통계의 값·상태·사유 유지 |
| 부분 장애 | 전역 `ai.state`와 단일 AI 결과 | 지표별 상태·사유 우선. 한 분기의 요청 실패가 다른 분기의 검증된 결과를 지우지 않도록 설계 |

공개 응답의 필드 이름과 버전은 BE·FE가 함께 확정한다. 현재 FE는 최상위 `basePeriod`와 AI 결과의 `base_period`가 같아야 응답을 받아들이므로, **기존 필드에 Q3을 넣고 Q2 위험도를 숨겨 담는 방식은 사용하지 않는다.** 지표별 기간을 담는 새 계약을 도입할 때 FE 파서도 같은 배포 범위에서 변경한다. `asOf`는 요청 전체의 정보 기준일이며, 각 관측 분기와 다르다. 가능한 경우 지표별 출처와 실제 사용 가능일도 함께 보여줄 수 있도록 BE와 정한다.

## AI 파트

- 기본 FastAPI `POST /predict`는 요청마다 `base_period`를 하나 받는다. 위험도·적합도는 그 분기에서 독립 판정한다.
- 서울 2026Q4 성장 예측은 연구 모드에서 Q3 매출 이력이 부족하면 Q2 기준으로 전환할 수 있다. 이 경우 성장의 실제 기준 분기는 `growth.base_period`를 사용하며 Q3 요청의 위험도·적합도는 요청 기준으로 표시한다. [분기 전환 계약](BACKEND_CONTRACT.md#서울-2026q4-성장-예측의-이전-분기-전환)
- 검증된 여러 분기가 필요하면 Spring이 분기별 내부 요청 결과를 조합하는 방식으로 우선 설계할 수 있다. 내부 API 확장 여부와 호출 횟수는 BE와 응답 계약을 확정할 때 결정한다. DB 조회 트랜잭션이 끝난 뒤 외부 호출을 수행한다.
- 매출이 없는 관측에서도 점포 수가 양수이고 상주인구와 양수 면적이 있으면 적합도 초안만 계산할 수 있다. 위험도는 필요한 매출·점포·폐업 입력이 없으면 `null`과 `missing_risk_indicators`다. 모델 준비 여부 등 선행 조건에 따라 성장 불가 사유가 달라지므로 매출 결측에 항상 `missing_sales`를 붙인다고 가정하지 않는다.
- AI 입력의 `source_kind=official` 선언만으로 출처·공개일·AI 사용 승인과 코드 대응이 증명되지는 않는다. Spring이 지표별 원천, 기간, 단위, 공개·사용 가능 시점, 승인 기록, 지역·업종 대응의 버전과 적용 기간을 검증해야 한다. 검증되지 않은 월별 현황을 과거 분기 입력으로 복제하거나 매출 결측을 0으로 채우지 않는다.
- 이 정책은 **결과 제공과 조합 방식**의 변경이다. 성장 예측 모델 재학습이나 서울 Q3 실측 매출 확보를 완료했다는 뜻이 아니다. 현재 위험도·적합도는 규칙 기반 초안 지수이며 확률이나 검증된 사업성 평가가 아니다.
- `tests/test_api.py`는 같은 가상 지역·분석일로 Q2 위험도와 Q3 매출 결측 적합도를 **서로 다른 v1 요청**에서 확인한다. Q2의 종료된 성장 대상은 `target_not_future`, Q3의 매출 결측은 모델 조건이 충족될 때 `missing_sales`로 확인한다. Spring의 승인 판단은 이 테스트로 증명할 수 없으며 별도 승인 근거 fixture와 FE→BE→AI 검증이 필요하다.

## FE 파트에 전달할 작업

1. `src/types/analysis.ts`와 `src/lib/aiAnalysis.ts`의 단일 분기 타입·검증을 지표별 기간을 받는 새 공개 계약으로 교체한다. 각 지표의 `status`·`reason`·`basePeriod`를 함께 검증하고 성장에는 `targetPeriod`도 확인한다.
2. `src/components/AiDiagnosis.tsx`의 공통 “달력상 최근 완료 분기” 헤더를 정보 기준일 설명으로 바꾸고, 성장·위험도·적합도 카드 각각에 기준 분기를 표시한다. 제공 불가 카드에도 확인한 기간이 있으면 표시한다.
3. `src/components/AnalysisPanel.tsx`, `src/lib/reports.ts`, `src/pages/Saved.tsx`의 단일 `result.period`가 전체 AI 결과의 기간처럼 보이지 않도록 고친다. 다운로드·저장 결과에도 각 지표의 기간과 사유를 남긴다.
4. 기간이 다른 점수를 종합점수로 계산하거나 한 시점의 단정적 해석으로 묶지 않는다. 현재 실제 AI 응답의 종합점수 `null`을 유지하고 각 지표를 따로 설명한다.
5. `src/lib/validation.ts`가 저장된 분석을 다시 검증하므로 새 응답 형식 적용 시 기존 v1 저장본을 보존할 방법(구버전 읽기 또는 명시적 변환)을 정한다. 단순 형식 변경으로 사용자의 저장 결과가 사라지지 않게 한다.
6. Q3 적합도·Q2 위험도·성장 불가, 한 지표만 제공 가능, 자료가 없는 지표, 구버전 저장본을 화면·보고서 테스트에 포함한다.

## 연동 확인 순서와 남은 결정

1. BE·FE가 지표별 기간·상태·사유와 공개 응답 버전을 확정한다. 최상위 단일 `basePeriod`의 폐지 또는 제한된 의미도 명시한다.
2. BE가 지표별 승인 자료와 유효 기간을 같은 읽기 스냅샷에서 확인하고, 읽기 트랜잭션 종료 후 필요한 FastAPI 호출을 수행한다. 매출 전무 시 전체 요청을 막는 조건을 지표별 판정으로 바꾸되, 매출 외 입력의 검증 근거를 생략하지 않는다.
3. AI는 내부 `/predict`의 부분 결과와 분기별 호출 사례를 계약 테스트로 고정했다. FE는 새 공개 응답과 기존 저장본을 함께 검증한다.
4. 승인된 지역·업종 조합 하나로 FE → Spring → FastAPI를 시험한다. 지표별 기간·값·`null`·사유·출처가 일치하는지 확인하고, 실패한 지표가 기본 통계와 다른 지표를 지우지 않는지 검증한다.

**현재 데이터 경계:** AI 프로젝트의 서울 상권분석 매출·점포 분기 원본은 2026Q2까지다. 위 Q3 적합도는 필요한 Q3 원천이 나중에 확보·승인된 상황을 가정한 정책 예시다. 전국 2026-09 점포 현황은 별도 원천이며 서울 Q3 입력으로 자동 승격하지 않는다.
