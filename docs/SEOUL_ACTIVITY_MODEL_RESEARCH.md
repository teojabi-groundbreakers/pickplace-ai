# 서울 활동 지표를 반영한 매출 성장률 후향 실험

작성일: 2026-11-11 (Asia/Seoul)
상태: **연구용 비교 학습 완료, 서비스 적용 보류**

## 이번에 결정한 경계

- 서울 **법정 용도지역**(주거·상업·공업·녹지)을 학습하지 않았다. 공식 공간 경계와 정답 레이블이 없으므로 인구로 법정 지정을 추측하지 않는다.
- 관측된 **활동 패턴**은 상주인구 총량, 길단위인구 총량 및 시간대 분포로 표현한다. 이 값은 매장 방문자·구매자 수나 법정 용도지역이 아니다. 별도 직장인구는 아직 확보하지 않았다.
- 매출 예측 목표는 기존 연구와 같은 `행정동 × CS 업종 × 목표 분기`의 **서울 추정매출 전년 동기 대비 증가율**이다. 대상 금액이나 개별 점포 매출, 성공확률을 예측하지 않는다.
- 서울만 비교했다. 경기의 카드매출·지역코드·단위 후보를 이 실험에 합치지 않았다.

## 입력과 검증

기존 [서울 분기 현황 인덱스](SEOUL_INDICATORS_API.md)의 매출·점포·상주인구·길단위인구와 원본 길단위인구 CSV의 시간대 6개 열을 사용했다. 인덱스에 있는 서울 추정매출 **376,485행**을 같은 분기·원본 8자리 행정동·CS 업종 기준으로 점포·인구와 정확히 연결했다. 인구 원본은 분기당 425개 동, 2021Q1~2026Q2 총 22개 분기다. 파일 해시, 원본 코드, 중복 키, 결측, 음수, 시간대 합계를 확인하고 불일치가 있으면 학습을 중단한다. 시간대 합계는 원본 총량과 반올림 차이 최대 6까지 허용한다.

시간대 구간 길이가 달라 11–17시(6시간), 21–06시(9시간), 17–21시(4시간)의 집계값을 **구간 시간 수로 나눈 상대 지수**를 만든다. 이는 자료의 공식 일평균 인구 또는 실제 시간당 고유 인원이라는 뜻이 아니다. 상주인구와 길단위인구의 서로 다른 집계 단위를 단순 비율로 나누지 않는다. 모집단 기준의 3분위 기준은 매출 관측이 있는 **9,334개 행정동·분기**에서만 산출됐으며, 법정 구역 레이블이나 검증된 주거/업무 분류가 아니다.

## 동일 표본에서의 비교

기존 `features.py`의 4분기 매출 특징·기준 분기와 **서울 CS 업종 코드**를 공통으로 쓰고 다음 네 구성을 비교했다. 업종 코드는 각 학습 구간에서만 범주 인코더를 맞췄다. 인구/활동 특징은 `log1p(상주 총량)`, `log1p(길단위 총량)`, 시간대 길이를 보정한 주간/심야·저녁/주간 상대 지수다. 점포 특징은 원본 전체 점포 수의 `log1p`이며 현재 영업 중인 점포 수라고 부르지 않는다.

| 후보 | 공통 매출·업종 특징 | 추가 특징 |
| --- | --- | --- |
| 매출·업종 | 포함 | 없음 |
| 매출·업종 + 인구·활동 | 포함 | 상주·길단위 총량, 시간대 상대 지수 |
| 매출·업종 + 점포 | 포함 | 동종 업종 전체 점포 수 |
| 매출·업종 + 인구·활동 + 점포 | 포함 | 위 두 집합 |

모두 동일한 HistGradientBoosting 설정과 표본을 사용했다. 목표 분기 전체를 시간순으로 나누고 평가 목표 직전 **1개 목표 분기를 비웠다**. 저매출·급변 입력을 찾는 탐색용 문턱값은 각 평가 분기보다 앞선 학습 입력에서만 산출했다. 네 후보는 같은 통과 표본으로 학습·비교했다. 보류된 원본은 삭제하지 않았으며 전체 표본의 오차도 메타데이터에 별도 기록했다. 문턱값은 오류 판정이나 현행 서비스 정책을 승인하는 근거가 아니다.

### 결과 — 보류 기준 통과 표본의 MAE, 단위 %p

| 후보 | 2025Q4 (14,112건) | 2026Q2 (14,111건) |
| --- | ---: | ---: |
| 매출·업종 | **19.366** | 22.191 |
| 매출·업종 + 인구·활동 | 19.401 | **22.184** |
| 매출·업종 + 점포 | 19.390 | 22.223 |
| 매출·업종 + 인구·활동 + 점포 | 19.389 | 22.215 |
| 0% 성장 기준선 | 26.161 | 29.219 |

전체 평가 표본은 각각 16,002건·15,961건이었다. 보류 기준 통과 비율은 약 88%로, 위 MAE는 **조건부 오차**다. 보류 표본을 포함한 전체 오차는 극단적 성장률에 크게 영향을 받으며 `metadata.json`의 `all` 항목에 남겼다. 시간대 상대 지수로 나눈 세 그룹에서도 두 평가 분기 모두 모든 그룹의 일관된 개선은 관찰되지 않았다.

**판단:** 인구·시간대 특징은 2025Q4에서 오차가 0.035%p 증가했고, 2026Q2에서는 0.007%p 감소했다. 점포 수와 인구·점포 동시 추가도 두 시점에서 매출·업종 기준보다 오차가 컸다. **일관된 개선이 확인되지 않았다.** 따라서 현재 자료만으로 “지역 활동 특성이 매출 예측을 개선한다”거나 “인구가 매출 변화의 원인이다”라고 주장하기 어렵다. 이 실험은 서울 단독·업종별 입력을 쓰므로 기존 서울·경기 공동 모델의 성능과 수치를 직접 비교하지 않는다. 기존 공동 모델과 FastAPI는 변경하지 않는다. 새 모델은 비교 연구 산출물로만 보관한다.

## 산출물과 재실행

- 특징 계산: `src/pickplace_ai/seoul_activity_features.py`
- 학습·비교: `scripts/train_seoul_activity_research.py`
- 누수·시간대 변환 검증: `tests/test_seoul_activity_research.py`
- 로컬 모델: `artifacts/seoul-activity-growth-research-20261111/final-model.joblib`
- 자세한 표본·문턱값·해시·오차: 같은 디렉터리의 `metadata.json`

모델 산출물은 Git 제외 대상이다. 로컬 파일의 신뢰를 확인하지 않은 채 `joblib`을 로드하지 않는다. 다음 명령은 **새 출력 경로**를 지정해야 하며 기존 결과를 덮어쓰지 않는다.

입력 인덱스·매니페스트·길단위인구 CSV의 지문은 읽기 전에 고정한다. 학습이 끝난 뒤 모델을 저장하기 전에 다시 확인하고, 직렬화 후 최종 경로에 발행하기 직전에도 대조한다. 읽기·학습·직렬화 중 입력 파일이 변경되면 오류로 종료하고 모델 폴더를 발행하지 않는다. 이 동작은 합성 입력 변경 회귀 테스트로 확인하며 기존 실제 모델을 다시 학습한 결과는 아니다.

```bash
cd /Users/factory/Documents/Projects/PickPlace/pickplace-ai
PYTHONPATH=src:. OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv/bin/python \
  scripts/train_seoul_activity_research.py \
  --snapshot data/processed/seoul/indicators-20261109 \
  --floating 'data/raw/seoul/floating_population/서울시 상권분석서비스(길단위인구-행정동).csv' \
  --output artifacts/seoul-activity-growth-research-new
```

최종 재학습 모델은 서울 CS 업종 63개와 보류 기준 통과 **261,473건**으로 학습했지만 **독립 평가값이 없다**. 이 모델은 인구·활동·점포 특징의 연구용 비교를 위해 보관했으며 운영 후보로 선택된 것이 아니다. 2025Q4와 2026Q2는 이전에도 확인한 기간이고, 현재 파일은 과거 분기의 최신 수정 스냅샷이라 당시 최초 공개·정정 시점을 증명하지 못한다. 위 수치는 실제 과거 시점의 실시간 예측 성능, 미래 정확도 또는 운영 승인 근거가 아니다. 이 모델을 기존 `/predict`나 `/research/unified/predict`에 연결하지 않았다.

## 다음 검증과 FE·BE 연결

1. 공식 용도지역 공간자료와 시점별 행정동 경계를 확보해 법정 지정 결과를 별도 제공한다. 행정동 전체를 한 용도지역으로 단정하지 않는다.
2. 서울 직장인구와 최신 기간의 인구·점포 공개 이력을 확보하고, 지역·업종·분기 기준 연결 및 실제 이용 가능 시점을 검증한다.
3. 새 기간의 아직 검토하지 않은 정답으로 시간순 평가를 수행한다. 같은 표본·보류 비율에서 업종/지역별 MAE, 중앙값 및 상위 오차를 비교한다.
4. 활동 특성은 먼저 **관측된 주간/야간 패턴과 근거**로 설명한다. 주거/상업/공업/녹지 확정 라벨이나 인과적 매출 설명으로 바꾸지 않는다. AI 내부 활동 특성 API는 아직 구현되지 않았다.
5. FE·BE의 코드 대응, 분기 표시, 법정 용도지역 조회, 부분 응답 작업은 [후속 이슈 초안](REGION_PROFILE_FE_BE_HANDOFF.md)을 참고한다.
