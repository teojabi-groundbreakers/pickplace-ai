# 지역 특성·상권 진단 연동: FE·BE 후속 이슈 초안

작성일: 2026-11-11 (Asia/Seoul)
상태: **2026-11-11 작성 시점의 작업 목록과 제안 계약**. FE·BE 구현 또는 AI 지역 특성 API의 존재를 뜻하지 않는다.

이 문서는 PickPlace의 화면 흐름을 **지역 특성 → 매출 현황·고객 수요·경쟁 환경 → 근거가 보이는 해석 → 검증된 범위의 예측 → 관련 지원사업**으로 확장할 때 FE·BE가 맡을 일을 정리한다. 사용자가 나중에 각 저장소의 GitHub 이슈로 옮길 수 있도록 책임과 완료 기준을 분리했다. 이번 작업에서 FE·BE 저장소는 수정하지 않는다.

## 작성일 당시 연결 상태와 먼저 합의할 사항

- FE의 `POST /analyses` 요청은 원본 **H10 지역 코드 문자열**과 선택 업종 코드를 전달한다. 실제 분석 응답은 데모 형식이며, 월별 차트는 점포당 월평균 매출(만원)·일평균 유동인구(명)를 전제로 한다. 서울 확보 원본은 분기 기준이고 월평균·일평균 산식이 확인되지 않았다. 서울 분기값을 월별로 복제·분할하거나 임의로 3배하지 않는다.
- AI에는 서울 매출·점포·상주인구·길단위인구의 분기별 원본 조회용 `/research/seoul/indicators`가 있다. 현재 인덱스/API는 인구 **총량**만 제공하며, 시간대·연령별 원본 열은 아직 API로 나오지 않는다. 서울·경기 공동 연구 예측 `/research/unified/predict`는 매출 이력만 쓰며 지역 특성·인구·점포를 예측 특징으로 사용하지 않는다. 기본 `/predict`와 세 API는 서로 다른 앱·계약이다.
- BE에는 기본 `/predict`의 내부 호출기와 조합 포트가 **추가 파일로 준비**됐지만, 승인된 분기 매출 조회 어댑터와 FE 공개 분석 컨트롤러는 아직 없다. AI 호출은 통계 읽기 트랜잭션을 종료한 뒤 실행한다.
- 법정 **용도지역**(주거·상업·공업·녹지)은 인구로 추정하지 않는다. [국토교통부 용도지역지구도](https://www.data.go.kr/data/15058773/openapi.do) 같은 공식 공간 자료로 조회한다. 행정동에는 여러 용도지역이 섞일 수 있다. 점포 위치의 지정 용도지역과 행정동 면적의 구성 비율은 별도 결과다. **활동 특성**(예: 주거 중심·업무 중심·혼합·판단 유보)은 인구·시간대 패턴을 근거로 하는 독립적인 분석 결과다.
- FE H10 ↔ 서울 `seoul-adstrd` 8자리 및 FE 업종 ↔ 서울 CS 업종 대응은 기준일·공식 근거·다대다 관계를 확인해야 한다. 이름 매칭, 코드 절단, `00` 덧붙이기를 운영 변환으로 쓰지 않는다.

## 공통 응답 계약 제안 — 확정 전

브라우저는 **Spring Boot만 호출**한다. BE는 공식 용도지역과 검증된 현황 원천을 조회하고, 필요한 경우 FastAPI의 활동 특성 결과·매출 예측을 내부 호출해 한 응답으로 조합한다. 활동 특성 내부 API 경로는 예를 들어 `POST /research/seoul/activity-profile` 또는 `POST /research/region-profile`을 검토할 수 있으나 **현재 구현된 경로가 아니며 AI·BE 공동 설계 후 확정**한다. 초기 AI 학습은 오프라인 연구이며 이 API의 가용성을 전제하지 않는다.

| 구분 | 필수 계약 요소 | 제한 |
| --- | --- | --- |
| 요청 식별 | FE 원본 H10, 선택 업종, 요청 좌표/필지의 필요 여부, 분석 기준일 `asOf`, 선택 분기 | 필지 지정 용도지역을 보여주려면 위치 정보가 필요하다. H10만 있으면 행정동 구성만 논의한다. |
| 코드 대응 | 원본/대상 코드 체계, 대응표 버전, 유효 기간, 승인·판정 상태 | 검증 실패 시 대상 지표 `null`과 사유. 원본 H10은 응답에도 유지한다. |
| 법정 용도지역 | 공식 제공처·자료 버전·공간 기준일, 지리 단위(필지/점/행정동 구성), 지정 유형 또는 비율, 상태·사유 | 혼합 행정동을 한 종류로 확정하지 않는다. 공식 지도 미확보 시 `null`. |
| 활동 특성 | 주거/업무/방문/혼합/판단 유보 등 **활동 패턴** 이름, 상태, 사용 지표와 기준 기간·원천, 규칙/모델 버전, 판단 근거 | 법정 용도지역처럼 표시하지 않는다. 보정·검증 없는 확률이나 원인·매출 기여도로 표현하지 않는다. |
| 현황 | 매출·인구·점포별 값, 단위, 관측 주기, 분기, 출처, 자료/게시 버전, `availableAt`, 상태·사유 | 서울 **추정매출**과 경기 **카드매출**을 구분한다. 총 유동인구를 일평균 방문자나 구매 고객으로 바꾸지 않는다. |
| 예측 | 대상 분기, 비교 분기, 증가율/예측액의 구별, 모델 버전, 기준 시점, 연구/운영 상태, 보류 사유 | 연구용 후향 추정을 검증된 미래 예측으로 표시하지 않는다. 인구 특징을 실제 학습·평가한 모델만 지역 특성을 예측 근거로 명시한다. |
| 지원사업 | 공고명·주관기관·신청 기간·대상 지역/업종·원문 URL·조회 시각, 상태 | 기업마당 수집과 사용 조건 검증 전에는 미제공. 공고를 매출 증가 원인이나 실제 수혜로 취급하지 않는다. |

각 항목은 `AVAILABLE`, `NO_DATA`, `UNAVAILABLE`, `NOT_LOADED` 등 팀이 확정한 상태와 **기계 판독용 사유 코드**를 갖고, 화면용 문구는 합의된 매핑으로 제공한다. 실제 원본의 0은 숫자 0, 미확보·보류는 `null`이다. 정상 지표는 AI 보류나 장애로 함께 사라지지 않는다. DB 장애는 정상적인 자료 없음 응답으로 감추지 않는다.

## BE 이슈 후보

### BE-1. 공식 용도지역 데이터 준비와 조회

- 공식 공간 원천의 라이선스·버전·좌표계·갱신 주기·효력일을 확인하고 별도 저장/캐시 및 출처 추적을 설계한다. FE의 실제 선택 위치로 필지/점 지정 여부를 확인할지, H10 행정동의 용도지역 구성 비율을 제공할지 먼저 합의한다.
- 행정동 구성이라면 **검증된 H10 경계와 용도지역 폴리곤의 공간 교차**로 비율을 산출한다. 경계가 없거나 시점이 맞지 않으면 미제공 사유를 반환한다. 한 점으로 전체 동을 대표시키지 않는다.
- 완료 기준: 원천·경계 버전 및 기준일이 응답에 남고, 혼합·경계 불일치·공간자료 미준비 테스트에서 임의 분류가 나오지 않는다. 공개 API와 이용조건은 별도 승인한다.

### BE-2. 공식 코드 대응·현황 스냅샷 연결

- H10·서울 8자리·업종 CS의 시점별 공식 대응과 승인 상태를 조회한다. 서울 분기 매출·상주/길단위인구·동종 점포의 자료 정의, 단위, 게시/공개 시점, 지역 범위, 누락·비공개 상태를 각각 검증한다.
- 기존 현황 조회의 T17/T18 의존 작업과 매출 원천 승인·게시를 완료한다. `SummaryContextService.withContext` 안에서 같은 스냅샷을 읽고, 그 결과를 물리적으로 확정해 트랜잭션을 끝낸 뒤 AI를 호출한다. 직장인구·시간대 자료는 수집/검증되기 전 선택 특징으로 취급한다.
- 완료 기준: 원본 H10을 보존하고, 대응 누락·경계 변경·분기 불일치·자료 미게시·원천 0/결측·DB 장애를 각각 구분한다. 같은 분석 응답의 각 값에 출처·기간·단위·가용성 사유가 추적된다.

### BE-3. 내부 AI 호출 및 공개 분석 조합

- AI가 활동 특성 계약을 확정한 뒤 내부 키·제한 시간·응답 검증을 갖춘 호출을 연결한다. 현재 준비된 `/predict` 클라이언트를 새 활동 특성 API와 동일 계약으로 취급하지 않는다. 예측 모델의 지원 범위와 사용 승인을 확인하고, 연구 결과의 보류 사유를 원문 코드로 보존한다.
- FE 공개 응답에 **법정 용도지역**, **활동 특성**, **매출/수요/경쟁 현황**, **종합 해석**, **예측**, **지원사업**을 항목별 부분 결과로 조합한다. 지원사업은 별도 수집 경로가 준비될 때까지 `null`과 사유로 둔다. 외부 자료/AI 장애가 발생해도 검증된 통계를 유지한다.
- 완료 기준: AI HTTP 200의 `unavailable`과 401/422/503·타임아웃을 구분하고, 키·원본 매출 이력·내부 오류 본문을 브라우저/로그에 노출하지 않는다. 실제 격리 DB·FastAPI·FE 계약을 이용한 통합 테스트를 통과한다.

## FE 이슈 후보

### FE-1. 결과 정보 구조와 단위·상태 표시

- 현재 `Analysis` 타입과 `TrendChart`의 **월별·만원·일평균** 고정 의미를 확장하거나, 분기 원본 전용 패널을 별도로 둔다. 월별 관측이 없는 서울 분기 자료로 월 차트를 채우지 않는다. 매출 원천을 서울 `추정매출`/경기 `카드매출`로 분명하게 표기한다.
- 화면을 ① 매출 현황 ② 고객 수요 ③ 동종 업종 경쟁 ④ 근거가 보이는 종합 해석 ⑤ 관련 지원사업으로 구성한다. 지역 특성 카드는 법정 지정과 활동 패턴을 서로 다른 제목/출처로 표시한다. 기간·자료 기준일·업종/지역 범위·관측 주기를 각 패널에서 확인할 수 있어야 한다.
- 완료 기준: 0, `null`+사유, 부분 결과, 준비 중, 장애, 연구용 예측 보류가 서로 다른 화면 상태로 검증된다. 지원사업 미수집·시간대 자료 미제공 시 해당 섹션만 이유와 함께 비워 둔다.

### FE-2. 지도 선택과 시점·출처 계약

- `POST /analyses`에 필요한 위치 또는 필지 식별자가 있는지 BE와 합의한다. 원본 H10을 유지하고 행정동 활동 특성과 점포 위치의 법정 용도지역을 혼동하지 않는다. 선택 지역·업종·분기가 바뀌면 이전 응답을 새 선택의 결과로 보여주지 않는다.
- 현재 합성 데모의 점수·요인·추천 문구를 실제 API 결과로 혼합하지 않는다. 모델이 제공한 성장률을 정확도·성공확률·확정 매출처럼 표현하지 않는다. 해석은 관측된 동행 관계와 근거를 표시하고 인과관계를 단정하지 않는다.
- 완료 기준: 원본 코드/지역/업종/기준일이 요청과 응답에서 일치하고, 늦은 응답·부분 실패·출처 변경을 FE 단위/계약 테스트로 확인한다. FastAPI 주소나 내부 키는 브라우저 번들에 없다.

## 진행 순서와 이슈 분리

1. **공동 계약 결정:** 법정 용도지역의 지리 단위(필지/점/행정동 구성), 활동 특성 유형·근거, 분기·월 표기, 부분 결과 DTO를 FE·BE·AI가 합의한다.
2. **BE 데이터 기반:** 공식 공간자료·코드 대응·승인된 분기 현황 스냅샷을 준비한다. 매출 원천의 집계 의미와 공개 시점을 확인한다.
3. **AI 오프라인 평가:** 활동 패턴의 정의와 인구 특징이 매출 예측을 개선하는지 시간순 비교한다. 개선이 검증되지 않으면 현황 설명만 제공한다. 법정 용도지역을 인구로 학습한 결과처럼 표시하지 않는다.
4. **BE 내부 API·공개 응답 및 FE 화면:** 승인된 결과부터 연결하고 보류·누락을 항목별로 표현한다. 실제 통합 테스트를 완료하기 전에는 기능 완료로 표시하지 않는다.
